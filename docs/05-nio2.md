# 05 · NIO.2：Path、Files、WatchService

Java 7 起，日常文件操作用 `java.nio.file`，不要再新写 `new File(...)` 一套，除非对接老 API。

## 1. Path 不是 File 的别名

`java.io.File` 是「某个文件的快照对象」。`Path` 是「路径的纯表示」，可以还不存在。

```java
Path p = Path.of("data", "demo.txt");   // 相对路径
Path abs = p.toAbsolutePath().normalize();
Path parent = p.getParent();
Path sibling = p.resolveSibling("other.txt");
```

`resolve`：相对拼接。`relativize`：算相对路径。`normalize`：去掉 `.` `..`。跨文件系统的 `relativize` 会抛异常。

与 `File` 互转：`path.toFile()` / `file.toPath()`。

## 2. Files：大多数时候你真正该用的 API

| 需求 | 方法 |
| --- | --- |
| 读全部字节 / 行 | `readAllBytes` / `readAllLines` / `readString` |
| 写全部 | `writeString` / `write` |
| 流式 | `newBufferedReader` / `newInputStream` / `newByteChannel` |
| 拷贝 | `copy(src, dst, REPLACE_EXISTING)` |
| 移动 | `move(..., ATOMIC_MOVE)`（是否真原子看文件系统） |
| 目录 | `createDirectories`、`list`、`walk`、`find` |
| 存在性 | `exists` / `notExists`（注意 TOCTOU 竞态） |
| 属性 | `size`、`getLastModifiedTime`、`readAttributes` |
| 删除 | `delete` / `deleteIfExists` |

`walk` 是深度优先流，**必须关掉 Stream**，否则目录句柄泄漏：

```java
try (Stream<Path> walk = Files.walk(root)) {
    walk.filter(Files::isRegularFile).forEach(...);
}
```

## 3. OpenOption 与 CopyOption

`StandardOpenOption`：`READ`、`WRITE`、`CREATE`、`CREATE_NEW`、`APPEND`、`TRUNCATE_EXISTING`、`SYNC`、`DSYNC`、`DELETE_ON_CLOSE`。

`CREATE_NEW` 在文件已存在时失败，适合做互斥标记文件。`SYNC` 会显著变慢，只在真正需要落盘语义时打开。

## 4. WatchService

监听目录的创建、修改、删除：

```java
try (WatchService watch = FileSystems.getDefault().newWatchService()) {
    dir.register(watch, ENTRY_CREATE, ENTRY_MODIFY, ENTRY_DELETE);
    WatchKey key = watch.take();          // 阻塞
    for (WatchEvent<?> event : key.pollEvents()) {
        Path name = (Path) event.context();  // 相对文件名
        // ...
    }
    key.reset();                          // 不 reset 就不再接收
}
```

注意：

- 默认 **不递归**。子目录要自己再 `register`。
- 事件是聚合的，一次保存可能触发多次 `MODIFY`。
- 溢出时会收到 `OVERFLOW`，意味着漏事件，需要全量对账。
- Linux 是 inotify，有用户实例监视数量上限（`fs.inotify.max_user_watches`）。

适合热加载配置、本地开发同步；不适合当分布式文件总线。

## 5. 文件锁与原子性

`FileChannel.lock` 是 **进程级** 建议锁或强制锁（平台相关）。同一 JVM 两个线程抢同一把锁的行为不要依赖。多进程互斥可以用 `CREATE_NEW` 文件，或真正的协调服务。
